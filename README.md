# Design Radar

面向中文设计师的静态设计发现页。构建期以低频方式读取公开入口并生成快照，浏览器只加载本仓库生成的静态数据，不会直接请求第三方站点。

> 项目是实验性的设计发现工具，不是实时服务或设计数据库。同步成功与否、条目数量和来源状态均以页面中的快照状态为准。

## 功能

- 按内容频道、来源类别和关键词筛选设计内容。
- 展示来源接入状态、同步时间和公开接入方式。
- GitHub Actions 每日刷新静态快照；单个来源失败时保留其最后一个可用快照。
- 适合部署到 GitHub Pages、Vercel 或 Netlify 等静态托管服务。

## 数据与使用边界

- 只读取已验证公开可访问的入口；不绕过 Cloudflare、登录、付费墙、验证码或 robots 限制。
- 不把站点地图的 `lastmod` 当成作品发布日期。卡片时间仅使用来源可靠的收录/奖项日期；无法取得可靠日期时应显示为首次发现日期。
- 卡片只保留来源公开提供的标题、缩略图、日期和原始链接，不下载、裁剪或托管原站大图。
- 同步器包含候选适配器，但候选来源不等于已验证或稳定来源。只有实际解析到可展示条目的来源才会显示为已接入。
- 第三方标题、缩略图、商标、页面截图及大量聚合内容可能受版权、商标、合同条款或数据库权保护。发布或新增来源前，应逐个核对 robots.txt、使用条款和 RSS 使用条件。

如你是权利人或来源运营者，希望移除某个来源或条目，请在本仓库提交 [Issue](https://github.com/xiyu519/design-radar/issues/new)，附上对应链接和移除理由。

## 本地运行

```bash
npm ci
npm run dev
```

访问终端输出的本地地址，通常为 `http://127.0.0.1:5173/`。

## 更新与验证

```bash
npm run fetch:feed
npm run build
```

`npm run fetch:feed` 最多写入 24 条近期内容。同步器使用明确的 User-Agent、20 秒超时和按来源回退的失败策略；若所有来源都无法生成可用内容，保留原有快照并以失败退出。

`.github/workflows/refresh-feed.yml` 会在每日 UTC 01:17 触发刷新，也可从 Actions 页面手动运行。`ci.yml` 会在每次 push 和 pull request 中执行可复现安装与生产构建。

## 部署

运行 `npm run build` 后，将 `dist/` 目录部署到任意静态托管服务。部署前请设置线上地址，并在仓库 About 中补充网站链接与项目主题。
